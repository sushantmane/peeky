# Rust engineering qualification

Historical scope of the original engineering gate (PR #22): a dependency-free Cargo fixture, strict input preflight and a bounded raw-DAP compatibility probe. Later sections of this document describe the experimental Rust worker and verification added since; see [RUST_AGENT.md](RUST_AGENT.md) for the investigation loop.

The fixture uses Rust/Cargo 1.96.0, edition2021, a request struct, mode enum, Some/None and a mutable i32 pagination offset. The probe builds a fresh copy offline, verifies the actual stopped source and loaded native module/symbol identity, inspects raw values, changes the scalar and checks changed output without rebuilding. It records tool/input hashes, bounded events and cleanup. No Rust Python formatters or project initialization scripts are loaded.

Local Apple LLVM21 qualification passed: the i32 local is displayed as `int`; struct fields and enum variant are readable. Raw Option storage includes a discriminant and union storage; the inactive None payload is not interpreted. The Some payload is deeper than the current worker expansion depth limit, so raw-DAP success does not yet qualify Option inspection through the worker. This is a narrow engineering observation, not a portable Rust formatter contract. macOS requires Cargo's packed dSYM and corresponding hashed binary under target/debug/deps; split-debug-info off discarded object files required for application symbols in this experiment. Linux LLVM18 is a separate CI gate.

The manifest validator accepts only one explicit binary and one immutable integration-test target, with autodiscovery/build scripts disabled, no dependencies/workspaces/profiles and a matching version4 lockfile. A separate ancestry check rejects implicit Cargo configuration and parent manifests. Production preparation must still combine these checks with a fresh CARGO_HOME, controlled environment, executable/artifact identities and repeated integrity checks; preflight alone is not isolation.

Run the optional probe using absolute real versioned cargo/rustc executables and explicit LLDB, dwarfdump and linker paths through PEEKY_RUST_* environment variables, then `pytest tests/rust`. The script accepts the same paths as named arguments. CI resolves tools using `rustup which --toolchain 1.96.0` and tests with LLVM18. The existing Python/Java/C/C++ lanes remain independent. No model calls run in required CI.

Next: implement the reviewed Rust runtime and compiled-test verification boundary in RUST_PLAN.md, including metadata/provenance failure tests and exact artifact test execution. The intentionally failing pagination Cargo test is an input for that future verification stage; it is not executed or claimed passing by this probe.

## Application-unit symbols and active variants

`peeky.rust_symbols` is the production symbol boundary used by `RustTarget` and the HTTP worker; the engineering probe also exercises it directly.

- **Line mapping.** One bounded `--debug-info --recurse-depth=0` index lists compile units. Only units whose recorded `DW_AT_comp_dir` string equals the canonical fresh workspace path (aliases are not resolved) *and* whose name is `<entrypoint>/@/<crate>.<hash>-cgu.<n>` are selected; a unit with only one of those properties is ambiguous and fails preparation. Selected units must be DWARF4, `DW_LANG_Rust`, produced by rustc, with distinct line tables (at most 16). All dwarfdump calls share one 30-second deadline. Each table is dumped by its exact `DW_AT_stmt_list` offset, its header offset must match, and the combined text goes through the unchanged fail-closed `parse_lines` with its 2 MiB limit. Standard-library tables are never parsed, so the C/C++ budget is not loosened. Fewer lines can only reject breakpoints/stops; standard-library line rows cannot be attributed to declared files.
- **Enum layouts.** The selected unit's DIE tree (bounded; depth-based indentation; every child list explicitly NULL-terminated; truncation and unknown rows rejected; every entry inside the unit's offset range) yields the compiler-emitted layout of each data-carrying enum. Only `core::option::Option<i32>` with one artificial discriminant, distinct 32-bit `DW_AT_discr_value`s for exactly `None` and `Some`, a fieldless `None` and a single `__0` payload is qualified; the discriminant and payload types are resolved through their referenced in-unit DIEs (four-byte `DW_ATE_unsigned` `u32` and `DW_ATE_signed` `i32` base types), never from dwarfdump labels. Niche layouts, other payloads, `Result`, user enums, types outside a pure namespace scope and conflicting definitions are `unqualified`.
- **Active-variant view.** `active_variant` validates the exact LLDB raw shape (`$variants$` → `$variant$<DW_AT_discr_value>` in DWARF order, typed for the named variant → `$discr$` and a `value` typed for that same variant), requires every discriminant view to agree and to be a compiled value, then reads only the active payload. Results are `Some(<i32>)` or `None` with no expansion handle. Unqualified enums are opaque without reading storage; any shape mismatch yields an opaque `<unverified Rust enum value>` instead of a guess. Inactive payloads are never fetched.

Local Apple LLVM 21 measurements (2026-10-14, Rust 1.96.0): one application unit, 22 declared `src/main.rs` lines including the observation line, application line table 103,840 bytes versus 1,752,464 bytes for the full dump, symbol extraction plus layouts 0.063 s; `Some(3)`/`None` from 9 bounded DAP fetches; whole probe 0.86 s. Linux LLVM 18 results are recorded from the hosted lane.

## Experimental Rust HTTP worker

`peeky.rust.RustTarget` (worker flag `--rust-config`) prepares one declared Cargo binary: validated manifest/lockfile, explicit real sysroot `cargo`/`rustc` (rustup proxies and mixed directories rejected) plus absolute adapter/dwarfdump/linker paths, pinned version check, a fresh workspace under an owned parent whose ancestry is checked for Cargo configuration, controlled environment (relative `CARGO_HOME`/`CARGO_TARGET_DIR` inside the workspace, explicit `RUSTC`, DWARF4 rustflags, incremental off, opt-level 0, packed macOS / unsplit Linux symbols, explicit Linux build ID) and fixed `cargo build --offline --locked --bin <name>`. `target/debug/deps` is a directory artifact, so every member is hashed and rechecked; exactly one hashed application executable, its `.d` file and (macOS) its dSYM are allowed. Symbols and enum layouts come from `rust_symbols`; module identity reuses the native UUID/build-ID helper.

`RustSession` reuses the native session's stop/module validation and adds: fixed `settings set target.load-script-from-symbol-file false`, mutation limited to root integer locals (`i16` to `i64`, `u16` to `u64`, `isize`, `usize`; LLDB's `short` to `unsigned long`) that the program keeps in memory, read back after each write, an active-variant value view, and refusal to expand raw `$variants$`/`$discr$` storage of enums missing from the application layouts. The worker exposes views with `variablesReference: 0` and a `view` label; view reads share a per-request budget (128 fetches, 10 s, 1,024 items, 1 MiB) with one absolute deadline covering each request's write and response. Exhaustion, including a read whose reply misses the deadline, is reported as `budget-exhausted`, distinct from an unverified shape; an incomplete write remains fatal. After any view read, mutation handles are bound to freshly re-acquired, identity-checked scopes, and any `$`-prefixed debugger field is refused at every level. Edits to tests, manifests and lockfile are rejected before tools run. Before **each** toolchain probe and Cargo command the exact staged manifest/lock are revalidated against the preflight result, workspace ancestry is rechecked, every previously probed tool and the original and staged sources are rehashed, and on macOS `PATH` must still resolve `dsymutil` to the executable resolved when preparation started; the pinned rustc/cargo versions are confirmed from probe output before any Cargo command runs. Only a complete Cargo JSON failure is retryable compiler feedback: Cargo's ordinary stderr footer, exactly one final `build-finished` failure, and only well-formed `compiler-message` errors (object message, list of span objects, not an internal compiler error) whose primary spans are all in declared sources; every message is scanned before deciding. Cargo infrastructure failures, timeouts, output overflow, test-target compile failures and drift of any previously probed tool are fatal. On macOS the declared tool must be named `dsymutil`, its directory is first on `PATH`, and `PATH` must resolve to exactly it. The worker gives each launch one 40 s deadline, below the client's 45 s HTTP timeout; cleanup after expiry has its own bounded grace. Rust, C/C++ and Java preparation and every DAP launch phase (initialize, launch write, initialized event, breakpoints, configurationDone, launch response) receive only the remaining budget, so exhaustion discards the launch promptly. Compile failures and close remove the workspace and owned parent; a failed removal is raised or attached to the original error, never ignored.

Real conformance (`tests/rust/test_rust_worker.py`) covers HTTP launch, `Some(3)`/`None`, struct expansion, fieldless enum, rejected Option/out-of-range/expression mutations, `start=0` producing the corrected first page, report, cleanup, source drift failing closed, and compile failure/frozen-test edits leaving no workspace.

**Mutations must reach the program.** At opt-level 0, rustc still keeps a local that is assigned once and never borrowed in a register. For the debugger it stores a copy (`<name>.dbg.spill`), which LLDB shows and writes but the program never reads. Builds therefore also emit LLVM IR (`--emit=link,llvm-ir`). A change is allowed only if every declaration of that local in the stopped function is a real memory slot; the function is matched by the symbol hash ending LLDB's frame name. Otherwise the change is refused rather than reported as applied. **Every compiled file is declared:** each file in rustc's dependency files for the application and test crates must be a declared source or test, so `#[path]` modules, `include!` and `include_str!` cannot bring in bytes that no check covers.

Compiled Cargo tests and independent candidate verification are described in [RUST_AGENT.md](RUST_AGENT.md). Not yet delivered: separate-host use, live-model Rust evaluation, and any Option payload other than i32. Raw probe traversal remains engineering evidence only.

## Optimized builds (opt-in)

`opt_level` (`"0"` by default, or `"1"`/`"2"`) sets `CARGO_PROFILE_DEV_OPT_LEVEL`, which is recorded in the target identity's profile. Locals with no value are reported as `unavailable`. Every result carries `optimized` and a warning, because optimized code can show wrong values that LLDB doesn't flag. In a real run, `start` read `1` at `opt-level 2` versus `3` unoptimized. See [COOKBOOK 7.5](COOKBOOK.md#75-optimized-builds).
