# Live agent evaluation: `peeky` CLI on the bug corpus (2026-10-15)

## Setup

- **Agents:** three independent general-purpose coding agents, run in parallel and with no shared context. Each agent was given only `docs/AGENT_GUIDE.md`, `docs/ERRORS.md`, the `peeky` CLI, and one corpus bug (`program.py`, `check.py` and the issue text). Reading the Peeky source was forbidden.
- **Tool version:** the CLI at `feat/corpus` 7ec3970, from the worktree's editable install.
- **Tasks:** fix the bug with a *general* fix verified by `peeky verify`. The prompts also asked the agents to try specific features:
  - `latest_version`: the basic workflow.
  - `mutable_default`: both a probe and a session.
  - `running_max`: `--json`, `--hits`, and verifying an overfit candidate before the real fix.
- **Environment note:** the agents' sandbox forbids writing under `/tmp`. Each agent copied its case into its own workspace and pointed `PEEKY_STATE_DIR` (and in one case `TMPDIR`) there. This did not change the checker or the verdict.

## Outcomes

| Case | Hypothesis evidence | Verified general fix | Overfit rejected | Peeky calls | Slowest call |
| --- | --- | --- | --- | --- | --- |
| `latest_version` | Probe showed `['10', '9']`. Setting the list to numeric order changed the output to `10`. | `sorted(versions, key=lambda v: tuple(int(p) for p in v.split(".")))` | The first attempt, `key=int`, was rejected (`'1.9'` is not an int). | 7 | 1.1 s |
| `mutable_default` | `--hits 2` showed `tags=['a']` on the second call. `set tags=[]` changed the output to `['b']`. | `tags=None` plus `if tags is None: tags = []` | n/a | 13 | 1.1 s |
| `running_max` | `--hits 3` showed `best` stuck at 0. `--set best=-3` produced the predicted `[-3, -1, -1]`. | Seed `best` from the first value. | `best = -3` was rejected on `[-10, -20]`. | 14 | 1.1 s |

All three agents reached `passed: True` on a general fix. Every overfit attempt was rejected. Probes took about 1 s and `verify` about 0.1 s. No agent hit a timeout or a hang.

## Findings and dispositions

Fixed on `feat/corpus` with regressions:

1. **`--set` evaluated arbitrary Python expressions in the debuggee.** The `running_max` agent found this: `min(values)` and `float('-inf')` were both accepted. Python values are now restricted to inert literal syntax (constants and containers of constants). They are checked against an AST allow-list and `ast.literal_eval` before reaching debugpy, and rejected values return `MUTATION_REJECTED`. `describe` and the docs now say "literals including containers", where they previously said "scalars". All three agents flagged this mismatch.
2. **`verify` leaked scratch directories.** One `peeky-verify-*` directory was left per call, and 131 had accumulated. The scratch copy is now deleted by default; `--keep` keeps it.
3. **Text-mode `verify` hid the failure reason.** Text output now prints `reason:` (the checker exception or build diagnostic) and the applied unified `diff`. JSON output always includes `stage` and `diff`.
4. **A breakpoint on a non-code line was silently moved** (line 9 to line 7). The probe now adds a `warnings` entry naming both lines.
5. **Fewer hits than requested reported only `completed`.** A warning now gives the count, for example "Only 3 of 5 requested hits".
6. **Probe failures had a different error shape** (`error` string, `error_code`, `hint`). Probe results now use the protocol error object, `{code, message, hint, retryable, session_closed}`, for `failed`, `no-stop` and `timeout`, including HTTP probe caps.
7. **`NOT_FOUND` told agents to "inspect", which a probe cannot do.** The message now lists the visible names.
8. **An `--old` mismatch was vague.** The error now gives the match count and the matching lines. If the text contains a literal `\n`, it explains how to pass real newlines.
9. **`session continue` printed only `state: stopped`.** It now reports the stop location, and hints what to do next when the program is running or has exited.
10. **"Interventions apply at hit 1 only" was undocumented.** It is now documented, and a probe warns when `--hits > 1` is combined with an applied intervention.

The items first deferred have since been delivered on `feat/agent-usability`:
- `--set-hit N`;
- Python names in scope per function in `describe`;
- negative indexes, refused unless the length is stated and all elements are visible;
- `by_hit`, which groups probe values per hit.

Still deferred: canonical path output (`/private/tmp` versus `/tmp` on macOS). Peeky reports resolved real paths on purpose, because confinement checks use them.

## Conclusion

With only the guide, an agent can observe a value, test a hypothesis and reach a verified general fix in a few one-second calls. The friction was in feedback quality, not capability: hidden reasons, silent relocation, and inconsistent error shapes. There was also one real safety gap in Python value validation. All of these were fixed in this slice.
